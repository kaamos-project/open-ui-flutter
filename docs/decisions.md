# Decisions

Lightweight ADRs: when a decision changes, update its entry and say why.

## No Material, no Cupertino

**Decision**: build only on the widgets layer, enforced by `test/architecture_test.dart`.
**Why**: an identical look on every platform, and no dependency on Material's design language.
**Trade-off**: we write and maintain things Material gives for free (text selection handles, copy/paste menu, focus, scroll behaviour).

## Same components as the web library

**Decision**: every component mirrors its `open-ui-web` counterpart (names, variants, keyboard behaviour, sizes from DESIGN.md).
**Why**: one design system, two implementations; apps look the same on web and native.

## Tokens from `open-design-tokens`, re-exported

**Decision**: depend on `kaamos_design_tokens` at a tag and re-export it.
**Why**: one source of truth for values; apps need a single dependency.

## Git dependency, no pub.dev (for now)

**Decision**: consumed from git, pinned to a tag or commit.
**Why**: no pub.dev publishing process to maintain while the library is young; pinned refs keep builds reproducible.

## Semantic theme, no `ThemeExtension`

**Decision**: `KaamosTheme` / `KaamosThemeData` with semantic fields.
**Why**: `ThemeExtension` lives inside Material's `ThemeData`. See [Foundation](foundation.md#theme-kaamostheme-and-kaamosthemedata).

## Lucide icons from the tokens package

**Decision**: icons are the Lucide set, as the `KaamosIcons` icon font generated by `open-design-tokens`; `KaamosIcon` takes an `IconData` and wraps Flutter's `Icon`. It replaces the 8 hand-drawn `CustomPaint` icons (and their `enum KaamosIcons`, which would have clashed with the tokens' class).
**Why**: 2,140 consistent icons, shared with the web, at the cost of only the glyphs used (icon tree-shaking).
**Trade-off**: a fixed stroke width (2px at 24px, ~1.33px at 16px), and `IconData` must always be `const`.

## No hover state, one density

**Decision**: like the web spec, no hover styles and the same 36px height everywhere.
**Why**: hover doesn't exist on touch; 36px is already above the WCAG AA touch target (24px).

## Only the visible tab panel is built

**Decision**: `KaamosTabs` builds only the active panel.
**Why**: lighter than an `IndexedStack`.
**Trade-off**: the state of a panel you leave is lost unless you keep it outside. See [Navigation](components/navigation.md#tabs--kaamostabs).

## Golden tests generated on Linux

**Decision**: goldens are the reference for the look, generated on Linux with a pinned Flutter version.
**Why**: pixel-exact comparison needs one rendering environment.
**Trade-off**: regenerating them on macOS or Windows breaks CI; Flutter upgrades are manual and come with new goldens.
